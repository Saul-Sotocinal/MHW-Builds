### No use of AI in this assignment.

## Approach

### Repository

The repository was not too bad although I had to make some changes from the README plan.

I had to create a charm interface to be used by the builds because it got a little messy when it was still considered armor.

I also havent implemented the monsters page with the api although it is still part of the database.

### Reducer + Context

Getting the reducer + context to work wasn't too bad, because I'd already used a context before for the previous assignment, and I was just able to copy over most of the reducer code from the labs and tweak it to fit with my app.

An issue I had while fetching from the DB was that I wasn't able to use async get operations in the equipment-selector.tsx component because the app would either crash because of re-renders not being done in the same order, or would become unresponsive because of an unresolved promise. The fix that I found was that I had to place the fetching logic in the parent component and just grab the data from the context in the equipment-selector and it worked fine that way.

Another big issue I had was getting multiple filters to work for the equipment selector. I had to scrap the idea of filtering equipment by rank because it was too complicated to get working with the name search.

### API Integration

For the API integration, I decided to extend the existing reducer because I thought that my use case for it was more similar to your pokemon example instead of your weather example.

I also modified the context a little by adding a cached weapons, armors, and charms array to it, so that it wouldn't need to fetch anything from the DB or the API if the user tries to change the same piece of equipment multiple times.
